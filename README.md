# بورتفوليو MN — النسخة الزرقاء

مشروعك نفسه بعد إعادة ترتيب الواجهة وتنظيف الملفات. يعمل بـ HTML وCSS وJavaScript، بدون React أو npm أو مرحلة بناء إلزامية.

## التشغيل

1. فك ضغط الحزمة.
2. افتح المجلد في VS Code، ثم شغّل `index.html` باستخدام Live Server.
3. افتح `admin/` من عنوان الموقع للدخول إلى لوحة التحكم. ويمكن استخدام `admin.html` أيضًا.
4. عند تحديث نسخة سابقة، حدّث الصفحة بـ Ctrl+Shift+R.

للنشر ارفع محتويات الحزمة إلى مجلد موقعك: `index.html` و`data.js` ومجلدا `assets` و`admin` وملف `.nojekyll`. يعمل المشروع على استضافة ثابتة أو GitHub Pages، سواء على الدومين مباشرة أو داخل مجلد مشروع.

## تحديث التواصل والخلفية

- تكبير قسم التواصل ومساحاته وعنوانه وروابطه.
- حركة خطوط إلكترونية ومدار خفيف خلف بيانات التواصل.
- خلفية ذرات صغيرة تتحرك وتتصل عند تقاربها؛ بعدد أقل على الهاتف وحد أقصى 30 إطارًا في الثانية.
- توقف المؤثرات عند إخفاء الصفحة، واحترام إعداد تقليل الحركة في الجهاز.
- إزالة زر Pause Motion وعبارة MN / PORTFOLIO أسفل المقدمة.
- ترتيب اللغات EN ثم TR ثم عربي في الموقع واللوحة.
- إصلاح مؤشر Contact عند النقر والوصول إلى نهاية الصفحة، مع خط ممتد أسفل الكلمة.

ارفع ملفات التحديث، بما فيها الملف الجديد `assets/js/effects.js`، ثم حدّث الصفحة بـ Ctrl+Shift+R. إذا كنت قد عدّلت `data.js` بعد النسخة السابقة، احتفظ بنسختك وصدّر `index.html` من اللوحة لتحديث محتواه الأولي أيضًا.

## التغييرات المنفذة

- شعار MN بدون نقطة في الترويسة والفوتر وأيقونة المتصفح واللوحة.
- كحلي وأزرق مع درجات سماوية خفيفة، ووضع فاتح بنفس الهوية.
- اسمك وصورتك في بداية الموقع. الصورة الأصلية محفوظة دون توليد وجه أو تعديل ملامح.
- حلقات وخطوط خفيفة حول الصورة؛ الحركة خارج مساحة الوجه. يُحترم إعداد تقليل الحركة في الجهاز دون زر إضافي في الواجهة.
- حذف نماذج Orbit وFrame وFlow والشهادات التجريبية من ملف البيانات. لم يُضف أي مشروع أو شهادة غير حقيقية.
- إخفاء قسم المشاريع أو الشهادات وروابطه تلقائيًا عندما لا يحتوي عناصر حقيقية منشورة. يظهر بمجرد إضافة محتوى وإتاحته للعرض.
- إزالة التكرار في النصوص، شريط التنقل العائم، النواة القديمة، والرسوم التجريبية.
- فوتر مختصر: الشعار وحقوق النشر والعودة للأعلى.
- الحفاظ على بيانات التواصل واللغات العربية والتركية والإنجليزية والسيرة الذاتية.
- فصل الصورة والسيرة الذاتية الأصليتين في `assets/profile`، وضغط الخطوط محليًا إلى WOFF.
- استبدال ملفات CSS المتراكمة بثلاثة ملفات واضحة، وحذف JavaScript والترجمات والأيقونات غير المستخدمة.

## لوحة التحكم

بيانات الدخول الموجودة في المشروع لم تتغير:

- المستخدم: `admin`
- كلمة المرور الحالية في الحزمة: `1234`

هذه لوحة تحرير محلية؛ حالة الدخول تحفظ داخل المتصفح، وليست مصادقة على خادم. المشروع لا يحتوي خادمًا أو قاعدة بيانات أو مفاتيح خدمة. هذا هو سلوك اللوحة الأصلية، وليس نشرًا مباشرًا إلى الاستضافة.

التحسينات الجديدة:

- معاينة صورتك أثناء تعديلها، مع شريط لتغيير موضع القص داخل الدائرة.
- تقسيم معلوماتك إلى: الهوية، الصورة والسيرة، النبذة، والتواصل.
- اختصار Ctrl+S أو Cmd+S للحفظ. داخل نافذة تحرير عنصر، يحفظ العنصر نفسه.
- زر معاينة واضحة للتعديلات المحلية.
- تغيير ظهور المشروع أو الشهادة من شارة الحالة في القائمة.
- العناصر الجديدة تبدأ كمسودات، ثم تختار إظهارها عند اكتمالها.
- نظرة عامة تبيّن الأقسام التي ستظهر للزائر.
- الحفاظ على الترتيب اليدوي، والترجمات، والاستيراد، والنسخ الاحتياطي.

## إضافة مشاريعك وشهاداتك

1. ادخل إلى المشاريع أو الشهادات وأضف عنصرًا حقيقيًا.
2. أضف التفاصيل والصورة أو ملف الشهادة وروابط المشروع إن توفرت.
3. فعّل خيار «منشور» أو اضغط شارة «مسودة» بعد حفظ العنصر.
4. أضف ترجمات العربية والتركية من صفحة اللغات. إذا تركت ترجمة فارغة، يُعرض النص الإنجليزي.
5. عاين الموقع ثم صدّر التعديلات.

التبديل إلى «ظاهر بالموقع» يعني أن العنصر سيدخل التصدير والمعاينة؛ لا يعني أنه رُفع إلى استضافتك بالفعل.

## الحفظ والنشر بعد التعديل

الحفظ المحلي يحفظ بياناتك في IndexedDB على الجهاز والمتصفح الحاليين. ظهور التعديل للزوار يحتاج رفع ملفات التصدير إلى الاستضافة.

من صفحة «نشر المحتوى»:

1. نزّل `data.js`.
2. نزّل `index.html`.
3. ارفع الملفين إلى جذر موقعك مكان نسختيهما، مع بقاء مجلدي `assets` و`admin`.

تصدير الصفحة مهم لإبقاء عنوانها ومحتواها الأولي موافقين لآخر تعديل، حتى قبل تشغيل JavaScript. لا تحتاج إلى تشغيل Node لهذا التصدير.

الملفات الجديدة التي ترفعها من اللوحة تُضمّن في `data.js`. الملفات الأصلية الموجودة داخل `assets/profile` تبقى ملفات مستقلة؛ احتفظ بمجلد `assets` عند نقل الموقع إلى استضافة أخرى.

عند أول تحديث ارفع الحزمة كاملة، لأن هيكل ملفات CSS تغير. ملف `data.js` وحده لا يطبق التصميم الجديد.

## العمل السابق في المتصفح

مفاتيح التخزين القديمة `nova-static-*` وأسماء `NOVA_DATA` و`NOVA_AUTH` بقيت للتوافق مع تعديلاتك السابقة.

إذا فتحت اللوحة على نفس عنوان النسخة القديمة، فقد تُستعاد بياناتك المحلية السابقة تلقائيًا. احفظ نسخة JSON احتياطية أولًا. إذا أردت اعتماد بيانات الحزمة الجديدة داخل اللوحة، اختر «استعادة النسخة المنشورة» من صفحة النشر. لا تحذف بيانات المتصفح لتحديث التصميم.

ملفات النسخ الاحتياطي JSON مخصصة لك وليست ملفات للنشر العام. عند نقل المشروع إلى جهاز آخر، انقل الحزمة كاملة مع `assets` ثم استورد النسخة الاحتياطية. بيانات الدخول لها تصدير مستقل من صفحة الإعدادات.

## التحقق

الفحوص المنفذة تشمل اللغات الثلاث، البيانات الأصلية، إخفاء النماذج والمسودات، ظهور الأقسام حسب المحتوى، مسارات الملفات، تغيير موضع الصورة، الحفظ وتبديل ظهور العناصر، تصدير HTML بالبيانات الحديثة، سلامة الروابط والتحقق من البيانات.

يمكن إعادة الفحص باستخدام Node دون تنزيل حزم:

```bash
node scripts/generate.mjs
node tests/check.mjs
node tests/effects.mjs
```

لم تتوفر معاينة بصرية أو اختبارات تفاعل في متصفح فعلي ضمن بيئة إعداد هذه الحزمة. لذلك لا يُقصد بفحوص Node أنها تحقق بصري كامل. افتح الموقع على الكمبيوتر والهاتف قبل النشر النهائي، وجرّب بريدك وروابط حساباتك. الروابط الخارجية محفوظة كما وردت في المشروع، ولم تُفحص حساباتها على الإنترنت.

## تطويرات مقترحة لاحقًا

1. **حفظ ونشر مباشرة من اللوحة:** ربطها بخادم مع تسجيل دخول فعلي وقاعدة بيانات. عندها تتم إدارة المشاريع والشهادات من أي جهاز دون تنزيل ملفات. يُختار نوع الخادم حسب الاستضافة التي ستستخدمها.
2. **مكتبة وسائط:** رفع الصور مرة واحدة وإعادة استخدامها، مع تصغير الحجم تلقائيًا والاحتفاظ بالأصل.
3. **سجل نسخ واسترجاع:** الاحتفاظ بنسخة من التعديلات قبل النشر والرجوع إليها من اللوحة.

هذه اقتراحات لاحقة وليست خدمات خلفية مضافة إلى الحزمة الحالية.
